# OneLLMRouter v1.5.0 Execution Task List

> Product design: `docs/superpowers/specs/2026-08-09-v1.5.0-plan.md`
>
> Approved baseline: `d9c5db1fb21eb8f1b2a9f05ec75728744f25df6d`
>
> Execution model: one isolated worktree and one stable Implementation Worker per Task.

## Contract Rules

- The approved product design is authoritative. A Task may not reinterpret product behavior.
- Each Task owns only its declared write scope. Reading other files is allowed; writing outside scope is not.
- A Worker must commit its implementation and report the full HEAD plus the listed verification evidence.
- A missing or contradictory decision is `design_gap`; the Worker must not resolve it by expanding scope.
- Tests use `httptest`, temporary directories, or dynamic loopback ports. They must not contact or stop the active Router.
- No Task may add Auto Failover, MCP, Skill, or Prompt management.
- Integration is serial even when implementation Tasks are independent.

## T1: Usage Data Contract

**Goal:** Add the protocol-neutral Usage record and preserve the distinction between an absent token field and an explicit zero.

**Dependencies:** None.

**Write scope:**

- `internal/usage/types.go`
- `internal/usage/types_test.go`
- `internal/translate/core_types.go`
- `internal/translate/core_adapter_test.go`
- `internal/translate/core_response.go`
- `internal/translate/types.go`

**Required contract:**

- Define the approved fields: time, request ID, Provider, requested/upstream model, protocol, five nullable token fields, source, attempt, and status.
- Token fields must represent `null`, `0`, and positive values distinctly.
- Protocol/source/status values must use closed constants rather than free-form call-site strings.
- Existing Anthropic/OpenAI translation behavior must remain compatible.

**Non-goals:** No file I/O, aggregation, CLI, proxy collection, or Qt changes.

**Acceptance:**

- JSON marshaling emits `null` for absent token values and `0` for explicit zero.
- Input/output/cache read/cache write/reasoning fields round-trip without loss.
- Existing translator tests remain green.

**Verification:**

```text
go test -count=1 ./internal/usage ./internal/translate
go vet ./internal/usage ./internal/translate
git diff --check
```

## T2: Usage JSONL Storage And Attempt Identity

**Goal:** Provide UTC daily JSONL storage and stable attempt identity for the protocol collectors added by T3.

**Dependencies:** T1.

**Write scope:**

- `internal/usage/store.go`
- `internal/usage/store_test.go`
- `internal/usage/reader.go`
- `internal/usage/reader_test.go`
- `internal/upstream/retry.go`
- `internal/upstream/retry_test.go`

**Required contract:**

- Store complete records under `~/.onellm/usage/YYYY-MM-DD.jsonl`, with an injectable base directory and clock for tests.
- Expose the same `request_id` across Retry and a one-based `upstream_attempt` to later collectors.
- Attempt ownership is enforced by collectors; the Store appends records without retaining an unbounded
  process-lifetime deduplication index, while aggregation ignores duplicate `request_id + upstream_attempt` records.
- A malformed line is reported by the reader and does not prevent later valid lines from being read.
- Persistence errors are logged with no secret/body data and do not replace a successful model response.

**Non-goals:** No production-path record emission, protocol parsing, stats aggregation, retention deletion, or UI.

**Acceptance:**

- UTC day rollover, append behavior, malformed lines, and write failures are covered by temporary-directory tests.
- Stored files contain no API key, Authorization header, request body, or response body.
- Retry exposes stable attempt identity without changing timing or response behavior.

**Verification:**

```text
go test -count=1 ./internal/usage ./internal/upstream
go test -race -count=1 ./internal/usage ./internal/upstream
git diff --check
```

## T3: Usage Collection Across Protocol Paths

**Goal:** Collect explicit upstream Usage for Anthropic Messages, OpenAI Chat Completions, and OpenAI Responses across stream/non-stream and direct/translated paths.

**Dependencies:** T2.

**Write scope:**

- `internal/proxy/handler.go`
- `internal/proxy/proxy_test.go`
- `internal/proxy/proxy_openai_test.go`
- `internal/proxy/proxy_responses_test.go`
- `internal/proxy/responses_sse.go`

- `internal/translate/types.go`
- `internal/translate/core_adapter_test.go`
- `internal/usage/collector.go`
- `internal/usage/collector_test.go`
- `cmd/onellm-router/main.go`

**Required contract:**

- Capture only fields explicitly returned by the upstream protocol; never estimate with a local tokenizer.
- Preserve upstream Usage fields even when the client-facing protocol exposes fewer fields.
- Record Retry attempts independently and never duplicate the final successful attempt.
- The Retry attempt observer is observation-only and must not change Retry decisions, timing, or failures.
- A stream without a terminal Usage event keeps token fields unknown.
- A response with no explicit token field keeps `usage_source` and all token fields unknown.
- Persistence failures are logged safely and never replace or alter a successful model response.

**Non-goals:** No aggregation, CLI, UI, or Retry-policy change.

**Acceptance:**

- A test matrix covers all three protocols, stream/non-stream, and direct/translated paths that exist in the Router.
- Missing and explicit-zero Usage remain distinct through capture and persistence.
- Retry/stream tests prove each upstream attempt has one record owner: the observer owns failed and buffered attempts, while the stream collector owns the accepted streaming attempt.
- A persistence failure test proves the original successful response remains unchanged.
- Stream byte/event order and failure behavior remain unchanged.

## T7: Core Configuration Commands

**Goal:** Provide secret-safe Core commands for Qt Provider/model read, validation, and atomic apply.

**Dependencies:** T5.

**Write scope:**

- `cmd/onellm-router/config_get.go`
- `cmd/onellm-router/config_get_test.go`
- `cmd/onellm-router/config_validate.go`
- `cmd/onellm-router/config_validate_test.go`
- `cmd/onellm-router/config_apply.go`
- `cmd/onellm-router/config_apply_test.go`
- `cmd/onellm-router/main.go`
- `internal/config/config.go`
- `internal/config/config_test.go`

**Required contract:**

- `config-get --json` returns only the editable `providers`, `codex.models`, and `model_slots` snapshot;
  each Provider exposes `api_key_set` instead of the stored `api_key`.
- `config-validate --json` reads the proposed editable snapshot from stdin and returns
  `{"valid": boolean, "errors": [{"field": string, "message": string}]}` without writing.
- `config-apply --stdin-json` accepts the same snapshot, validates it, writes the exact pre-apply YAML to
  the sibling `<config>.bak`, and atomically replaces the selected YAML.
- Apply modifies only `providers`, `codex.models`, and `model_slots`; Server, Log, global Proxy, Retry,
  and every other section remain untouched.
- Unknown fields and existing comments survive edits within the managed sections.
- Provider `prefix` is the identity used for secret preservation. An omitted `api_key` preserves the old
  key for the same prefix; a changed or new prefix must provide `api_key` explicitly. `api_key_set` is
  output metadata and never supplies secret input.
- The backup is a secret-bearing, restorable pre-image: it retains the old API key and source file mode,
  never contains the proposed replacement key, and is never echoed or logged.

**Non-goals:** No Server/Log/global Proxy/Retry editor, generic configuration framework, reflection-driven
schema merger, hot reload, Qt UI, credential vault, or modification of an external attached Core.

**Acceptance:**

- Failure at parse, validation, backup, or replace leaves the original config unchanged.
- Secret-leak tests prove stdout, stderr, logs, and validation errors contain neither old nor proposed API
  keys; backup tests prove the exact old YAML/key is retained, the proposed key is absent, and permissions
  are not broadened where the platform exposes file modes.
- Existing configuration loading and validation tests remain green.

**Verification:**

```text
go test -count=1 ./internal/config ./cmd/onellm-router
go test -race -count=1 ./internal/config ./cmd/onellm-router
git diff --check
```
