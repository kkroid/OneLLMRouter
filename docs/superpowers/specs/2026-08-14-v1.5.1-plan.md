# OneLLMRouter v1.5.1 小版本计划

> 状态：实现、审查与本地回归完成，待提交和发布（2026-08-17）
>
> 基线：v1.5.0
>
> 目标：修正多协议 Provider 的模型归属表达、显示运行中 Core 版本、消除 Setup 升级时的重复托盘启动，并改善 Usage 查询体验。

## 1. 版本范围

v1.5.1 包含四项用户可见改动：

1. Provider 模型可按上游端点声明，解决同一 Provider 在 Anthropic、OpenAI Chat 和 OpenAI Responses 线路上返回或接受不同模型名的问题。
2. 托盘图标的运行状态 tooltip 在状态文本后显示当前 Core 版本号。
3. Setup 不再在完成页额外启动托盘；升级运行中的托盘时只由 Windows Restart Manager 恢复一次。
4. Usage Token 使用紧凑格式显示，支持今天、本月和包含起止日期的自定义区间自动查询，并兼容缺少请求模型的历史记录。

本版本不移除手动模型配置，不改变自动发现优先级，不增加 Auto Failover、MCP、Skill、Prompt 管理，也不调整 Retry 策略。v1.5.1 尚未发布，因此模型配置直接切换到端点对象格式，不保留旧字符串格式兼容。

## 2. 端点级模型配置

### 2.1 配置契约

模型配置使用对象格式：

```yaml
models:
  - id: deepseek-v4-pro[1m]
    endpoints: [anthropic]
  - id: deepseek-v4-pro
    endpoints: [openai, responses]
```

- `id`：客户端可见并用于 `provider/model` 选择的模型名。
- `endpoints`：必填；允许使用该模型的上游线路，可选值为 `anthropic`、`openai`、`responses`。
- `upstream_model`：可选；当客户端模型名与该线路实际接受的模型名不同时，指定发送给上游的模型名。

### 2.2 运行时行为

- Resolver 按实际上游线路选择模型，不按客户端请求协议简单过滤。
- OpenAI Chat 请求优先使用允许的 OpenAI 直连模型；没有直连模型时，仍可使用允许的 Anthropic 模型进行协议翻译。
- Anthropic、OpenAI 和 Responses 模型目录只返回声明给对应线路的模型。
- Claude Code 模型槽位只接受 Anthropic 模型；Codex 预览和 catalog 只使用 Responses 模型。
- 手动发现结果记录用户选择的发现线路；Qt 加载和保存时必须保留 `endpoints` 和 `upstream_model`。
- 未配置任何模型时，继续使用现有的上游动态发现和命名空间动态路由行为。

### 2.3 DeepSeek 预期配置

```yaml
models:
  - id: deepseek-v4-pro[1m]
    endpoints: [anthropic]
  - id: deepseek-v4-flash[1m]
    endpoints: [anthropic]
  - id: deepseek-v4-pro
    endpoints: [openai, responses]
  - id: deepseek-v4-flash
    endpoints: [openai, responses]
```

Claude Code 保留官方文档使用的 `[1m]` 名称；OpenAI Chat 和 Responses 使用其模型目录返回的无后缀名称。对象配置按声明路由，不增加 DeepSeek 专属的隐式规则。

## 3. 托盘运行状态版本号

### 3.1 显示规则

- Router 为 `Healthy` 时，托盘 tooltip 在本地化状态文本后追加版本，例如 `OneLLMRouter - 健康 · v1.5.1` 或 `OneLLMRouter - Healthy · v1.5.1`。
- 优先显示 `/health` 返回的 Core `version`，保证附着外部 Core 时显示实际运行版本。
- 只有健康数据缺少版本时才回退到桌面编译时的 `ONELLM_VERSION`。
- `Stopped`、`Starting`、`Conflict` 和 `Error` 没有已确认运行 Core，不追加版本号。
- 托盘菜单首行已有版本显示，保持现有格式；通知标题和正文不变。

### 3.2 刷新边界

当前 `setState()` 在状态未变化时提前返回。实现必须让新的健康数据到达时也刷新 tooltip，避免 Core 重启或外部附着后仍显示旧版本。建议把图标和 tooltip 更新提取为一个小的展示函数，由状态变化和健康数据更新共同调用，不引入新的状态管理层。

## 4. 版本与发布元数据

发布前统一更新以下默认版本到 `1.5.1`：

- `build.ps1`
- `desktop/CMakeLists.txt`
- `.github/workflows/release.yml`
- `installer/onellm-router.iss` fallback
- 中英文 README 的构建产物示例
- 中英文 Changelog 的 v1.5.1 发布日期和比较链接

发布仍只产出 Windows x64 便携版和 Setup；不增加 Linux/macOS 安装包。

Setup 首次安装完成后不自动启动，用户从开始菜单启动；升级运行中的托盘时保留 Windows Restart Manager 恢复，并移除完成页的第二条启动路径。

## 5. 实施任务

当前进度：T1 至 T5 已完成实现、审查、本地完整回归、staged 桌面 smoke 和 v1.5.1 便携版与 Setup 构建，待提交和发布。

### T1：端点级模型契约与 Core 路由

- 完成严格对象解析、字段校验、端点过滤、可选上游模型映射和精确匹配优先级。
- 覆盖 Anthropic 直通、OpenAI 直通/翻译、Responses 直通和模型目录。
- 验收：旧字符串配置被拒绝；DeepSeek 三条模型目录返回各自正确名称；错误线路请求在到达上游前被拒绝。

### T2：Qt 配置与客户端模型过滤

- Qt 保留对象模型字段，发现结果绑定所选线路。
- Claude 和 Codex 下拉框按 Anthropic/Responses 线路过滤。
- 验收：配置 round-trip 不丢字段或 API Key；外部 Core 继续只读。

### T3：托盘 tooltip 版本显示

- 使用实际 Core 版本生成健康状态 tooltip。
- 健康状态不变但版本更新时仍刷新。
- 增加中文、英文、版本回退和非运行状态测试。

### T4：v1.5.1 发布收口

- 更新版本元数据、README 和 Changelog。
- 构建便携版和 Setup，验证升级保留现有配置。
- 移除 Setup 完成页启动，只保留 Windows Restart Manager 的升级恢复。
- 使用更新后的本地配置验证严格对象契约；实际 DeepSeek 三条线路由发布前体验确认。

### T5：Usage 查询体验

- Token 总量使用 K/M/B 紧凑格式，tooltip 保留精确值，不在表格中展示无法补算的缺失字段计数。
- Core 增加包含起止日期的 `stats range START END`，Qt 提供今天、本月和自定义区间并自动查询。
- 缺少 `requested_model` 的历史统计行显示为未记录，不再使整组结果解析失败。
- 验收：区间包含开始与结束日期；结束日期选择后自动查询；日历可重复打开；宽屏筛选栏保持紧凑。

## 6. 验证与完成标准

```text
go test ./...
go test -race ./...
go vet ./...
pwsh -NoProfile -File ./build.ps1 -TestOnly
cmake --build desktop/build --config Release
ctest --test-dir desktop/build -C Release --output-on-failure
pwsh -NoProfile -File ./tools/release-workflow-contract-test.ps1
pwsh -NoProfile -File ./tools/installer-upgrade-contract-test.ps1
pwsh -NoProfile -File ./tools/desktop-smoke.ps1 -Tray ./desktop/stage/onellm-router-tray.exe -ProtectedPorts 3456,3457
git diff --check
```

版本完成必须同时满足：

- 对象模型配置可加载、校验和保存，旧字符串格式被明确拒绝。
- 三类上游端点只暴露并接受分配给自己的模型。
- 托盘健康 tooltip 显示实际 Core 版本。
- Setup 升级不覆盖用户配置和 API Key，且只恢复一个托盘进程。
- GitHub Actions 的 Go/Qt 跨平台门禁与 Windows 发布任务通过。
